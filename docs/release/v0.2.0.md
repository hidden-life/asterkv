# AsterKV v0.2.0
AsterKV v0.2.0 is the CLI response rendering and client UX foundation release.

This release builds on `v0.1.0` and improves the user-facing `astercli` experience.

## Release scope
AsterKV v0.2.0 includes:
- `AsterKV::Client` module;
- client-side protocol response parsing;
- client-side pretty response rendering;
- pretty output by default in `astercli`;
- pretty output for local command mode;
- pretty output for TCP single-command mode;
- pretty output for TCP REPL mode;
- shell-friendly `astercli` error and exit-code policy;
- improved TCP REPL UX;
- REPL-side `help` and `?` commands;
- case-insensitive REPL-side `help`, `?`, `exit`, and `quit`;
- graceful REPL goodbye message;
- CLI response rendering tests;
- CLI stdout/stderr/exit-code tests;
- TCP REPL UX smoke tests.

## User-facing CLI output
`astercli` prints human-readable responses by default.

Examples:
```text
PONG
OK
alex
1
error: not_found key not found
```

The CLI does not expose a public raw protocol output mode in this release.

Raw protocol behavior remains covered by protocol-level tests and TCP smoke tests that use
`nc`.

## Single-command TCP mode
Start server:
```bash
./build/debug/apps/asterd/asterd \
    --listen 127.0.0.1:7721 \
    --max-clients 8 \
    --idle-timeout 30 \
    --log-level warn
```

Run commands:
```bash
./build/debug/apps/astercli/astercli --connect 127.0.0.1:7721 PING
./build/debug/apps/astercli/astercli --connect 127.0.0.1:7721 SET username alex
./build/debug/apps/astercli/astercli --connect 127.0.0.1:7721 GET username
./build/debug/apps/astercli/astercli --connect 127.0.0.1:7721 EXISTS username
```

Expected output:
```text
PONG
OK
alex
1
```

## Local mode
```bash
./build/debug/apps/astercli/astercli --local PING
```

Expected output:
```text
PONG
```

## TCP REPL mode
```bash
./build/debug/apps/astercli/astercli --connect 127.0.0.1:7721
```

Example:
```text
AsterKV TCP REPL
Connected to 127.0.0.1:7721
Type 'help' for commands, 'exit' or 'quit' to leave.
asterkv > help
AsterKV REPL commands:
    help, ?         Show this help message
    exit, quit      Exit REPL mode

Server commands:
    PING
    SET <key> <value>
    GET <key>
    DEL <key>
    EXISTS <key>
asterkv > PING
PONG
asterkv> SET username alex
OK
asterkv > GET username
alex
asterkv > quit
Goodbye.
```

## Error and exit-code policy
Successful protocol responses:
```text
stdout
exit code 0
```

Protocol-level errors:
```text
stderr
exit code 1
```

TCP/client failures:
```text
stderr
exit code 1
```

Response parsing/rendering failures:
```text
stderr
exit code 1
```

Example:
```bash
./build/debug/apps/astercli/astercli --connect 127.0.0.1:7721 GET missing_key
```

Output:
```text
error: not_found key not found
```

Exit code:
```text
1
```

## REPL error behavior
Protocol errors do not immediately terminate TCP REPL mode.

The REPL continues accepting commands.

If at least one command failed during the session, the REPL process exits with code
`1` after the user exits the session.

## Supported server commands
AsterKV v0.2.0 keeps the same command set as `v0.1.0`:
```text

GET

```

## Testing
Clean build:
```bash
rm -rf build/debug

cmake --preset debug
cmake --build --preset debug
```

Full test suite:
```bash
ctest --preset debug --output-on-failure
```

Focused CLI/client tests:
```bash
ctest --preset debug -R "astercli|asterkv_client_tests" --output-on-failure
```

## Current limitations
AsterKV v0.2.0 intentionally does not include:
- public raw output mode in `astercli`;
- command history;
- autocompletion;
- persistent TCP client sessions;
- client-side command validation;
- persistent storage;
- WAL;
- snapshots;
- replication;
- Raft;
- clustering;
- authentication;
- TLS;
- benchmarks.
