# AsterKV v0.3.0

AsterKV v0.3.0 is the storage durability planning and WAL foundation release.

This release adds the first end-to-end foundation for preserving basic key-value mutations through a write-ahead log when `asterd` is explicitly started with a WAL file.

## Release scope

AsterKV v0.3.0 includes:

- `AsterKV::Wal` module;
- WAL record model;
- WAL record validation;
- versioned WAL serialization format;
- `AKVWAL1` WAL record format;
- hex-encoded WAL key/value fields;
- WAL file writer foundation;
- WAL file reader foundation;
- WAL replay foundation;
- WAL-backed in-memory storage foundation;
- optional `asterd --wal-file <path>`;
- `wal_file` server config option;
- startup recovery from WAL file;
- TCP `SET` and `DEL` mutation logging when WAL is configured;
- WAL recovery integration smoke test;
- WAL architecture documentation and ADRs.

## WAL record model

Supported logical WAL record types:

```text
Set
Del
```

These correspond to the current mutating commands:
```text
SET <key> <value>
DEL <key>
```

Each WAL record contains:
```text
sequenceNumber
type
key
value
```

## WAL serialization format
Current serialized WAL record format:
```text
AKVWAL1 <sequence> <type> <key_hex> <value_hex>
```

Example:
```text
AKVWAL1 1 set 757365726e616d65 616c6578
AKVWAL1 2 del 757365726e616d65 -
```

Decoded:
```text
1 set username alex
2 del username
```

## Using WAL with asterd
Start `asterd` with a WAL file:
```bash
./build/debug/apps/asterd/asterd \
    --listen 127.0.0.1:7721 \
    --max-clients 8 \
    --idle-timeout 30 \
    --log-level warn \
    --wal-file ./data/asterkv.wal
```

Then write data:
```bash
./build/debug/apps/astercli/astercli --connect 127.0.0.1:7721 SET username alex
./build/debug/apps/astercli/astercli --connect 127.0.0.1:7721 GET username
```

Expected output:
```text
OK
alex
```

After stopping and starting `asterd` again with the same WAL file:
```bash
./build/debug/apps/astercli/astercli --connect 127.0.0.1:7721 GET username
```

Expected output:
```text
alex
```

## Config file
`asterd` can also enable WAL through config:
```ini
listen = 127.0.0.1:7721
max_clients = 8
idle_timeout_seconds = 30
log_level = warn
wal_file = ./data/asterkv.wal
```

## Recovery behavior
When `wal_file` or `--wal-file` is configured, `asterd`:
```text
opens the WAL file if it exists
reads records in file order
deserializes WAL records
replays SET/DEL mutations into in-memory storage
accepts TCP clients after successful recovery
appends future SET/DEL mutations to the WAL
```

If the WAL file does not exist yet, startup succeeds and the file is created on
the first mutation.

## Important durability note
AsterKV v0.3.0 is still a foundation release.

It does not provide production-grade durability guarantees.

The WAL writer currently flushes the C++ stream, but this is not the same as an
operating-system-level `fsync`.

## Current limitations
AsterKV v0.3.0 does not yet include:
- fsync policy;
- checksums;
- corruption recovery policy;
- partial recovery policy;
- WAL segment rotation;
- snapshots;
- compaction;
- production durability guarantees;
- replication;
- Raft;
- clustering;
- authentication;
- TLS.
